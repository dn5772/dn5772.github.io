# seam 개발 일지 #8 - 데몬, 설치 마법사, 그리고 멈춘 자리

#7까지 오면 기능은 다 있음. 근데 쓸 수 있는 물건은 아니었음.

데몬을 어떻게 띄우는지, 재부팅하면 어떻게 되는지, 처음 설치한 사람이 뭘 해야 하는지가 비어 있었음.

# 🔁 00:43 — start / stop / restart 

1

00:43  feat: seam start/stop/restart + seam service install/uninstall

seam start 가 데몬을 띄움. 게이트웨이(:11400)랑 IPC 소켓(daemon.sock)이 같이 올라감.

구조가 좀 특이한데, 바이너리가 자기 자신을 다시 실행함.

1
2

seam start  →  seam __gateway  (hidden command)
seam run    →  seam __daemon --env-yaml <path>

__gateway, __daemon, __agent 는 clap에서 hide = true 로 숨겨둔 커맨드임. seam --help 에는 안 나오는데 내부적으로 자기를 부를 때 씀.

이렇게 한 이유는 단일 바이너리를 지키려고임. 데몬 실행 파일을 따로 두면 설치할 게 두 개가 됨. #3에서 Rust를 고른 이유가 “curl | sh 한 줄"이었는데, 그걸 끝까지 밀려면 파일이 하나여야 함.

# 재부팅해도 살아 있게 

1
2

seam service install     # macOS LaunchAgent 등록
seam service uninstall

프록시라서 항상 떠 있어야 의미가 있음. 로그인할 때마다 seam start 를 쳐야 하면 아무도 안 씀.

macOS만 구현했고 Linux systemd는 안 했음. 지금도 안 되어 있음.

# 🐛 01:26 — 이름 하나 빠져서 안 뜨던 데몬 

1

01:26  fix: __gateway 이름 누락 + config.toml 하위 호환 파싱

__gateway 를 clap enum에 정의는 했는데 디스패치에서 빠져 있었음. seam start 가 조용히 아무것도 안 함.

같이 고친 게 설정 파일 하위 호환임. #6에서 router_slider, ollama_base_url, classifier_model 을 추가했는데, 그 전에 만들어진 config.toml 에는 그 필드가 없음. 파싱이 통째로 실패해서 설정이 날아감.

없으면 기본값을 쓰게 바꿨음. 설정 파일은 한 번 만들어지면 사용자 기계에 계속 남으니까, 새 필드는 항상 옵셔널이어야 함.

# 🧙 01:52 — 설치하고 처음 켰을 때 

1

01:52  feat: seam setup — 대화형 초기 설정 마법사

seam start 를 처음 치면 setup이 자동으로 뜸. first_run 을 감지해서.

물어보는 건 이런 것들임.

  • API 키 (anthropic / openai / google / github) → OS 키체인에 저장
  • 라우팅 슬라이더 0~9
  • Ollama 쓸 건지, 주소는 어딘지

dialoguer 로 만들었음. 설정 파일 포맷을 문서에서 찾아 읽게 하는 것보다 이게 나음. 특히 API 키를 어디다 둬야 하는지는 물어보는 게 맞음. 안 그러면 다들 환경변수에 평문으로 둠.

# 🌏 14:11 — 마지막 커밋 

1

14:11  feat: setup wizard 언어 선택 + EN/KO 완전 이중 언어화

setup 첫 질문이 언어 선택이고, CLI 출력 전체를 영어/한국어로 갈랐음.

그리고 이게 마지막 커밋임.

# 🕳️ 안 만든 것들

정직하게 적으면 이만큼 비어 있음.

  • seam journal / seam budget — stub만 있음. #1의 킬 메시지가 “AI 활동 영수증"이었는데 그게 비어 있음
  • journal.rs 는 작성됐는데 프록시에서 호출을 안 함
  • seam logs --follow — 미구현
  • seam service — macOS만. Linux systemd 없음
  • Trust Sandbox (Layer 2) — 통째로 없음
  • Lazy Skill Router (Layer 3) — seam.yaml 에 필드만 있고 구현 없음
  • 에이전트 통신 버스 — 없음
  • Semantic Memory — 없음. Episodic + Shared만
  • hub.seam.dev — 레지스트리는 GitHub 레포로 대체

#1에서 적었던 6레이어 중 실제로 만든 건 Layer 0, 1, 4 세 개임.

# 💭 배운 것

# 설계를 먼저 쓰면 싸게 버릴 수 있음

#2에서 일주일 만에 방향을 통째로 갈아엎었는데, 코드가 한 줄도 없는 상태였음. Sprint 1~7을 반쯤 짜고 알았으면 훨씬 아팠을 것.

문서 쓰는 게 느려 보여도, 버릴 때 손해가 작음.

# “안 보이는 제품"은 설명이 안 됨

v0.4는 “백그라운드에서 메모리를 주입하는 투명한 레이어"였음. 기능은 같은데 설명이 안 됐음. seam.yaml 이라는 파일 하나를 중심에 두니까 한 문장으로 끝남 — “Docker처럼 AI 환경을 공유함”.

# 조용한 실패가 제일 위험함

  • #3 — HTTP 4xx/5xx를 안 보고 지나감
  • #4 — 종료 코드 0이 아닌데 성공 반환, 루프 상한에서 말없이 종료
  • #5 — accept 루프가 통째로 죽음
  • #7 — 라우터 응답이 비면 기본값으로 조용히 넘어감

전부 다른 날 다른 언어에서 나왔는데 같은 모양임. 에러를 안 내고 “그럴듯하게” 계속 가는 코드.

# 빠른 게 마냥 좋진 않았음

3개월 계획을 사흘에 밀어넣은 건 기분이 좋았는데, 결과를 보면 넓고 얕음. 레이어 6개 중 3개, 킬 기능인 journal/budget은 stub, Linux는 미지원.

돌이켜보면 Phase 1만 제대로 끝냈으면 쓸 수 있는 물건이 됐을 것 같음. “설치만 하면 AI가 나를 기억함 + 오늘 AI가 쓴 돈” 딱 여기까지. 그게 #1에서 정한 MVP 범위이기도 했음.

기능을 넓히는 속도가 붙으니까 범위를 지키는 쪽이 오히려 어려웠음.

# 🎯 지금

3/27 이후로 멈춰 있음.

버린 프로젝트는 아니고, 멈춘 자리가 명확하다는 정도임. 돌아온다면 새 기능이 아니라 journal이랑 budget부터 할 것 같음. 그게 원래 제일 처음에 보여주기로 한 거였음.
