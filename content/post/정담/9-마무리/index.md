# 정담 개발 일지 #9 - 마지막 버그 하나, 그리고 넉 달 회고

[#8]({{< ref "/post/정담/8-모바일" >}}) 이후 두 달 동안 조용했음. 잘 돌아갔으니까.

그러다 5월에 **메뉴 저장이 갑자기 안 되기 시작함.**

## 🐛 3월에 고친 게 5월에 다시 터짐

```
fix: add allowOverwrite to Vercel Blob put to fix menu save failures
```

[#7]({{< ref "/post/정담/7-보안" >}})에서 레이스 컨디션 고칠 때 `list → del → put` 을 **같은 경로 덮어쓰기**로 바꿨었음.

```js
await put('menuData-ko.json', body, { addRandomSuffix: false });
```

그 사이에 Blob SDK 메이저 버전이 올라갔음.
그리고 **같은 경로에 덮어쓰려면 `allowOverwrite` 를 명시적으로 줘야** 하게 바뀜. 안 주면 에러.

```js
await put('menuData-ko.json', body, {
  addRandomSuffix: false,
  allowOverwrite: true,   // ← 추가
});
```

한 줄 추가로 끝났음.

근데 이게 좀 재밌는 게, **덮어쓰기를 실수로 하는 걸 막으려고 SDK가 막아둔 거임.** 나는 일부러 덮어쓰는 건데.
3월에 `del` 을 없앤 그 결정이 5월에 손이 한 번 더 간 셈인데, 그래도 메뉴가 잠깐 비는 것보단 나음.

## 💭 넉 달 동안 배운 것 4개

### 1. "로컬에서 되는데요"가 제일 무서움

[#4]({{< ref "/post/정담/4-저장소" >}})에서 파일 쓰기가 로컬에선 100% 돌아갔음. 배포 환경이 다르다는 걸 코드가 알려주지 않음.
그리고 메모리로 바꾼 것도 **똑같은 착각을 다른 방식으로 반복한 것**이었음 — "이 프로세스가 계속 살아 있다"는 전제.

진짜 고쳐야 했던 건 저장 위치가 아니라 그 전제였음.

### 2. DB 없이도 되는 게 꽤 많음

메뉴판처럼 **작고, 자주 안 바뀌고, 동시 수정이 없는** 데이터는 JSON 두 장으로 충분했음.
스키마 마이그레이션이 없으니 넉 달 동안 데이터 구조 바꾸는 게 파일 고치는 일이었음.

다만 이건 "DB는 오버엔지니어링"이라는 얘기가 아님. 조건이 맞아서 된 것.
동시에 수정하는 사람이 둘만 됐어도 이 구조는 바로 깨짐.

### 3. 저장 형식이랑 편집 형식은 달라도 됨

[#5]({{< ref "/post/정담/5-다국어-설계" >}})의 결론인데 제일 오래 남을 것 같음.

```
손님:    menuData-ko.json 한 장만 받음        (가볍게)
관리자:  ko/en 합쳐서 { title: {ko, en} }     (편하게)
경계:    저장할 때만 쪼갬
```

조회가 압도적으로 많고 수정은 거의 없는 화면이라 가능한 선택이었음.

### 4. 조용히 실패하는 버그가 제일 오래 삶

[#7]({{< ref "/post/정담/7-보안" >}})의 레이스 컨디션은 **에러를 안 냄.** 그냥 메뉴가 잠깐 비어 보임.
아무도 신고 안 해주고 로그에도 안 남음. 두 달을 살아남았음.

인증 없던 업로드 엔드포인트도 마찬가지임. 잘 작동했음 — 너무 잘 작동해서 아무나 쓸 수 있었던 것.
