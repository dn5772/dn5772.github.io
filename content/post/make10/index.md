# make10 - 반드시 다 지워지는 퍼즐판 만들기

사과에 숫자가 적혀 있고, 드래그해서 네모를 그리면 그 안의 합이 10일 때 사과가 사라지는 게임임.
다들 한 번쯤 해봤을 그거.

- 플레이: <https://make10-lime.vercel.app>
- 코드: <https://github.com/dn5772/make10>

Next.js App Router로 만들었고 **서버 상태가 아예 없음**. 클라이언트 컴포넌트 트리 하나가 전부임.

## 🍎 제일 고민한 것: 판이 진짜 다 지워지나?

숫자를 랜덤으로 깔면 게임은 돌아감. 근데 **끝까지 지울 수 있는 판이라는 보장이 없음.**
마지막에 3이랑 4만 덩그러니 남으면 그건 게임이 아니라 그냥 고장임.

그래서 생성 방식을 뒤집었음. 숫자를 깔고 검사하는 게 아니라, **합이 10인 조각으로 판을 타일링**함.

```
1. 빈 구역을 row-major로 훑는다
2. 첫 빈 칸에 랜덤 타일 모양(2~6칸)을 얹는다
3. 그 타일을 합이 정확히 10인 숫자로 채운다
4. 구역이 꽉 찰 때까지 반복
```

이러면 **구역 전체가 타일 단위로 반드시 분해됨.** 처음부터 정답을 깔아두고 시작하는 셈임.
물론 플레이어가 그 정답대로 지울 필요는 없고, 다른 조합으로 지워도 됨. 다만 "최소한 하나의 해는 존재한다"가 보장됨.

타일 모양은 가중치를 줘서 뽑음.

```ts
const TILE_SHAPES = [
  { h: 1, w: 2, weight: 5 },   { h: 2, w: 1, weight: 5 },
  { h: 1, w: 3, weight: 2 },   { h: 3, w: 1, weight: 2 },
  { h: 2, w: 2, weight: 1 },
  { h: 1, w: 4, weight: 1 },   { h: 4, w: 1, weight: 1 },
  { h: 1, w: 5, weight: 0.5 }, { h: 5, w: 1, weight: 0.5 },
  { h: 2, w: 3, weight: 0.3 }, { h: 3, w: 2, weight: 0.3 },
];
```

2칸짜리가 제일 흔하고 큰 조각은 드물게. 큰 조각만 나오면 너무 쉬워지고, 2칸만 나오면 단조로워짐.

간혹 막다른 길에 걸리는데, 그럴 땐 **구역 전체를 최대 80번까지 다시 만듦.** 그래도 안 되면 fallback으로 균등 랜덤을 깔되 구역 합이 10으로 나눠떨어지게 보정함. 실제로 fallback까지 가는 경우는 거의 못 봤음.

## 🗺️ 판을 6구역으로 쪼갠 이유

판 전체를 한 번에 타일링하면 **한쪽 구석에 9가 우르르 몰리는 일**이 생김.
난이도가 위치에 따라 널뛰니까 별로임.

그래서 판을 6개 구역으로 나누고 **각 구역을 독립적으로 생성**함. 가로 판이면 5×6, 세로 판이면 6×5.
구역마다 따로 타일링하니까 숫자 분포가 판 전체에 고르게 퍼짐. 그리고 각 구역이 독립적으로 클리어 가능하니까 판 전체도 자동으로 클리어 가능함.

## 📱 화면 방향에 따라 판이 뒤집힘

전체 180칸은 고정인데 배치가 바뀜.

| 환경 | 배치 |
|---|---|
| 데스크탑 · 가로 폰 | 10×18 |
| 세로 폰 | 18×10 |

`window.innerHeight > window.innerWidth` 로 판별함. 마운트할 때 한 번 재고, 재시작할 때 다시 잼.

그래서 **게임 중에 폰을 돌려도 지금 판은 그대로 유지되고, 다음 판부터 새 방향을 따름.** 중간에 판이 뒤집히면 그게 더 당황스러울 것 같아서 이렇게 함.

크기 맞추는 건 `ResizeObserver` 로 함. 판의 `cols / rows` 비율을 유지하면서 컨테이너에 들어가는 제일 큰 박스를 계산해서 가운데 정렬. 가로 판이 좁은 화면에서 넘치거나, 세로 판이 너무 길어지는 걸 이걸로 막음.

## 💥 hydration 에러로 한 번 데였음

판 생성에 `Math.random()` 이 들어감. 그런데 서버랑 클라이언트에서 다른 값이 나오니까 **React hydration mismatch가 바로 터짐.**

해결은 단순함. 초기 상태를 서버·클라이언트 **둘 다 `null`** 로 두고, 마운트 후 `useEffect` 에서 판을 만듦.

```
서버 렌더: board = null → 같은 비율의 빈 자리만 그림
클라 마운트: useEffect → createBoard() → 진짜 판
```

판이 없는 동안엔 같은 비율의 빈 박스를 그려서 레이아웃이 안 튀게 했음.
랜덤이 SSR에서 아예 안 돌게 하는 게 핵심임.

## 🎮 모드 3개랑 홈 버튼

| 모드 | 시간 |
|---|---|
| 빠르게 | 120초 |
| 보통 | 180초 |
| 무제한 | 제한 없음 (카운트 업) |

무제한은 타이머가 **거꾸로 올라감.** 그래서 `time` 이 그대로 경과 시간이 되고, 결과 화면에서 "몇 초 걸렸는지"로 씀. 유한 모드는 남은 시간을 보여주고.

고른 모드는 `localStorage` 의 `make10:mode` 에 저장함.

초기 버전은 홈 버튼이 **게임을 바로 재시작**했는데, 써보니까 모드를 바꾸고 싶어서 누른 건데 같은 모드로 다시 시작해버려서 답답했음. 그래서 홈 버튼을 `idle` 상태로 보내서 **모드 선택 화면이 뜨게** 바꿨음. 커밋 하나짜리 수정인데 체감이 컸음.

## 🌏 3개 국어

한국어 / 영어 / 일본어. 서버 라우팅이나 URL prefix 없이 클라이언트 컨텍스트로만 처리함.

문자열은 정적 딕셔너리에 넣었는데, 값이 그냥 문자열일 수도 있고 함수일 수도 있게 했음.

```ts
winSubtitle: (seconds: number) => `${seconds}초 남기고 클리어!`
```

이러면 보간이 타입 안전해짐. 언어 감지는 `localStorage`(`make10:lang`) → `navigator.language` → 영어 순서로 폴백하고, 바꿀 때 `document.documentElement.lang` 도 같이 갱신함.

## 📲 모바일 대응

드래그로 노는 게임이라 확대/축소가 걸리면 게임이 안 됨.

- `Viewport` 에서 `maximumScale: 1, userScalable: false`
- `globals.css` 에서 tap highlight랑 overscroll 끔
- 좁은 화면에선 HUD 라벨을 숨기고 아이콘만 남김 (`Score` 라벨 숨김, 언어 선택은 글자 하나로)
- 모바일은 `svh` 단위로 화면 꽉 채우고, `sm` 브레이크포인트부터는 가운데 정렬된 둥근 카드

## 🎯 느낀 점

제일 재밌었던 건 **"랜덤으로 깔고 풀리나 검사한다"를 "풀리는 걸 깔아둔다"로 뒤집은 지점**임.
검사하는 쪽으로 갔으면 판정 로직도 짜야 하고, 실패하면 다시 돌려야 하고, 그래도 보장은 안 됐을 것.

타일링으로 바꾸니까 생성이 곧 증명이 됨. 코드도 훨씬 짧아졌음.

hydration 에러는 매번 까먹고 매번 당함.. 랜덤이랑 SSR은 같이 두면 안 된다는 걸 또 배웠음.
