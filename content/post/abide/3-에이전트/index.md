# ABIDE 개발 일지 #3 - 답을 주지 않는 AI를 만들기

[#2]({{< ref "/post/abide/2-백엔드" >}})에서 만든 AI 서버의 본체다.

이 앱의 어려운 점은 **AI가 답을 잘 해주면 안 된다**는 거다.

"이 구절 무슨 뜻이야?" 에 바로 해설을 주면 그건 묵상이 아니라 검색이다.
되물어야 하는데, 끝없이 되물으면 사람이 지친다. **언제 되묻고 언제 정리할지**를 판단해야 한다.

그래서 노드를 여러 개로 쪼갰다.

## 노드 일곱 개

LangGraph로 Supervisor → Worker 패턴을 짰다.

| 노드 | 역할 |
|---|---|
| **Supervisor** | 지금 어느 노드로 갈지 결정 |
| **Planner** | 대화 방향 계획 |
| **Counselor** | 소크라테스식 되묻기 — 본체 |
| **Observer** | 지금 얼마나 깊이 들어왔는지 판정 |
| **Scribe** | 묵상 노트 작성 |
| **ConfirmEnd** | 마무리할지 물어봄 |
| **WrapUp** | 정리하고 종료 |

핵심은 **Observer랑 Supervisor의 관계**이다.

Counselor가 계속 되묻기만 하면 대화가 안 끝난다. Observer가 "지금 깊이가 어느 정도인지"를 점수로 매기고,
Supervisor가 그 점수를 보고 **더 파고들지 / 마무리로 갈지**를 정한다.

이 판정 로직을 [#7]({{< ref "/post/abide/7-스트리밍" >}})에서 한참 고치게 된다. 첫 버전은 너무 빨리 "깊어졌다"고 판단했다.

## 무한 루프를 막은 카운터

15일 커밋에 이게 있다.

```
feat: 노트 요청 처리 개선 및 wrap_up 반복 방지 카운터 추가; LLM 호출 시 HumanMessage로 변경
```

`WrapUp` 이 **자기 자신으로 다시 돌아가는** 경우가 있었다.
정리를 하고 끝내야 하는데 그래프가 다시 WrapUp을 고른다. 사용자 입장에선 같은 마무리 인사를 두 번 세 번 받는다.

LLM 판단에만 맡기면 이런 게 생긴다. **반복 횟수를 세는 카운터**를 상태에 넣어서 끊었다.

에이전트 그래프에서 LLM이 라우팅을 하면 편한데, **종료 조건만큼은 코드로 박아야** 하는 것 같다.

## LLM 호출을 빼서 빨라짐

14일 첫 커밋이 이거다.

```
최적화 및 기능 추가: LLM 호출 제거, 템플릿 기반 응답으로 성능 향상;
상태 관리 개선 및 API 키 검증 미들웨어 추가
```

**LLM을 부르던 자리를 템플릿으로 바꿨다.**

전부 LLM에 맡기면 코드는 단순한데 느리고 비싼다. 그런데 실제로 보면 **LLM이 필요 없는 자리가 꽤 있었다.**
인사말, 상태 전이 안내, 고정 문구 같은 건 템플릿이면 충분하다. 매번 생성할 이유가 없다.

[seam]({{< ref "/post/seam/6-router" >}})에서 복잡도 분류를 로컬 모델로 돌린 거랑 같은 얘기다.
**"이 자리에 진짜 추론이 필요한가"** 를 매번 따지는 게 비용에서 제일 크게 먹힌다.

## RAG는 pgvector로

```
feat: Implement Meditation Agent Nodes and RAG Service
```

신학 자료를 청크로 쪼개서 임베딩하고, 묵상 중에 관련 내용을 끌어온다.
[#2]({{< ref "/post/abide/2-백엔드" >}})에서 적었듯 별도 벡터 DB 없이 **Postgres + pgvector** 하나로 간다.

솔직하게 적으면 이 부분은 **끝까지 완성 못 했다.**
신학 RAG 청크 129개는 만들어뒀는데, `theology_vectors` DB 시딩 스크립트를 안 썼다. CLAUDE.md에 그대로 "미완료"로 남아 있다.

## 쿼터를 DB에 박았음

AI 호출은 돈이 듦. 그래서 [#2]({{< ref "/post/abide/2-백엔드" >}})의 Core 서버가 관문 역할을 하는데, 그 근거 테이블을 infra에 만들었다.

```
Add user quotas system and performance indexes for optimization
```

쿼터를 **Redis가 아니라 Postgres에** 뒀다. 정확도가 더 중요해서다.
Redis가 재시작되면 쿼터가 초기화되는데, 그건 "무제한 무료"랑 같은 말이다.

DeepLens 쿼터는 30일에 200회로 잡았다. 나중에 [#7]({{< ref "/post/abide/7-스트리밍" >}}) 즈음에 DB 캐시를 붙이면서 **올렸음**. 사전 계산된 걸 꺼내 쓰는 거면 호출 비용이 거의 안 드니까.

## 프롬프트는 커밋 안 함

```
servers/ai/app/prompts/     ← gitignored
servers/ai/app/private/     ← gitignored
```

프롬프트랑 일부 노드 구현을 저장소에서 뺐다.

공개 레포는 아니지만 **프롬프트가 이 앱의 실질적인 자산**이라서 분리해뒀다.
코드 구조는 공유해도 되는데 "어떻게 되묻는지"는 다르다.

CLAUDE.md에도 굵게 적어뒀다. *never commit these.*

## 느낀 점

**"AI가 답을 안 하게 만드는 것"이 답하게 만드는 것보다 훨씬 어려웠다.**

되묻기만 하면 짜증나고, 답을 주면 묵상이 아니다. 그 사이를 판단하는 게 Observer인데, 이게 이 프로젝트에서 제일 오래 붙든 부분이 된다.

그리고 **에이전트 그래프에서 종료 조건은 LLM한테 맡기면 안 된다.**
wrap_up 무한 반복이 그 증거였다. 흐름은 LLM이 잡아도 **"그만"은 코드가 세야** 한다.

다음은 로그인이랑 푸시다.
